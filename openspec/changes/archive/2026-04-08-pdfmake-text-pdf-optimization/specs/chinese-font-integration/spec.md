## 2. 功能需求

### 2.1 核心功能

#### 2.1.1 中文字体支持
- **需求ID**: CF-001
- **优先级**: 高
- **描述**: 系统必须支持中文字符的正确显示和渲染
- **验收标准**:
  - 中文字符在PDF中可正常显示
  - 无乱码、缺字现象
  - 支持常用中文字符集（GB2312）

#### 2.1.2 字体按需加载
- **需求ID**: CF-002
- **优先级**: 高
- **描述**: 字体文件应在用户需要导出PDF时才加载
- **验收标准**:
  - 应用启动时不加载字体文件
  - 用户点击导出按钮后开始加载字体
  - 加载过程显示进度提示

#### 2.1.3 离线支持
- **需求ID**: CF-003
- **优先级**: 高
- **描述**: 系统必须在离线环境下正常工作
- **验收标准**:
  - 字体文件打包到应用包中
  - 无需网络连接即可使用
  - 离线环境下PDF导出功能正常

#### 2.1.4 字体缓存
- **需求ID**: CF-004
- **优先级**: 中
- **描述**: 字体加载后应缓存在内存中
- **验收标准**:
  - 首次加载后字体保存在内存
  - 后续导出无需重新加载
  - 缓存失效时能自动重新加载

### 2.2 辅助功能

#### 2.2.1 加载进度提示
- **需求ID**: CF-005
- **优先级**: 中
- **描述**: 字体加载过程需要向用户显示进度
- **验收标准**:
  - 显示加载状态和进度
  - 提供友好的加载提示文案
  - 支持取消操作

#### 2.2.2 错误处理
- **需求ID**: CF-006
- **优先级**: 中
- **描述**: 字体加载失败时提供降级方案
- **验收标准**:
  - 自动重试机制
  - 降级到内置字体
  - 友好的错误提示

## 3. 技术规格

### 3.1 字体文件规格

#### 3.1.1 字体选择
- **字体名称**: 思源黑体 (Source Han Sans SC)
- **字体格式**: TTF (TrueType Font)
- **授权协议**: SIL Open Font License 1.1
- **字符集支持**: GB2312 + 扩展字符

#### 3.1.2 字体文件清单

| 文件名 | 字重 | 文件大小 | 用途 |
|--------|------|----------|------|
| SourceHanSansCN-Light.ttf | Light (200) | ~2.8MB | 细体文本 |
| SourceHanSansCN-Regular.ttf | Regular (400) | ~2.9MB | 常规文本 |
| SourceHanSansCN-Bold.ttf | Bold (700) | ~2.9MB | 粗体文本 |

**总计大小**: ~8.6MB

### 3.3 接口规范

#### 3.3.1 字体管理器接口

```typescript
interface ChineseFontManager {
  // 检查字体是否已加载
  isLoaded: boolean

  // 检查是否正在加载
  isLoading: boolean

  // 检查并加载字体
  checkAndLoadFonts(): Promise<boolean>

  // 加载字体文件
  loadFonts(): Promise<boolean>

  // 注册字体到pdfmake
  registerFonts(fontFiles: FontFile[]): void

  // 卸载字体（释放内存）
  unloadFonts(): void

  // 获取字体状态
  getStatus(): FontStatus
}

interface FontFile {
  name: string
  data: ArrayBuffer
  size: number
}

interface FontStatus {
  isLoaded: boolean
  isLoading: boolean
  loadedSize: number
  totalSize: number
  error: string | null
}
```

#### 3.3.2 字体配置接口

```typescript
interface FontConfig {
  // 字体名称
  name: string

  // 字体文件路径映射
  files: {
    normal: string
    bold: string
    light?: string
    italics?: string
    bolditalics?: string
  }

  // 字体显示名称
  displayName: string

  // 是否启用
  enabled: boolean

  // 加载优先级
  priority: number
}
```

### 3.4 性能规格

#### 3.4.1 加载性能
- **字体加载时间**: ≤ 3秒 (在普通网络环境下)
- **内存占用**: ≤ 15MB (字体加载后)
- **首次渲染时间**: ≤ 500ms

#### 3.4.2 运行时性能
- **PDF生成时间**: ≤ 5秒 (A4单页简历)
- **内存使用峰值**: ≤ 100MB
- **CPU使用率**: ≤ 50% (生成过程中)

#### 3.4.3 应用启动性能
- **应用启动时间**: ≤ 2秒 (不受字体影响)
- **初始包大小增长**: +8.6MB

## 4. 实现规范

### 4.1 字体加载流程

#### 4.1.1 初始化阶段
```
字体管理器初始化流程
1. 创建字体管理器实例
2. 设置初始状态 (isLoaded=false, isLoading=false)
3. 注册字体配置文件
4. 等待用户触发加载
```

#### 4.1.2 按需加载流程
```
按需加载执行流程
1. 用户点击"导出PDF"按钮
2. 检查字体是否已加载
   ├─ 已加载 → 直接开始生成PDF
   └─ 未加载 → 进入加载流程
       ├─ 显示加载提示
       ├─ 并行加载3个字体文件
       ├─ 注册字体到pdfmake
       ├─ 更新加载状态
       └─ 开始生成PDF
```

#### 4.1.3 字体注册流程
```
字体注册到pdfmake流程
1. 验证字体文件完整性
2. 设置pdfMake.vfs虚拟文件系统
3. 配置pdfMake.fonts字体映射
4. 验证字体注册成功
5. 更新管理器状态
```

### 4.2 错误处理规范

#### 4.2.1 错误类型定义

```typescript
enum FontErrorType {
  NETWORK_ERROR = 'NETWORK_ERROR',
  FILE_NOT_FOUND = 'FILE_NOT_FOUND',
  INVALID_FORMAT = 'INVALID_FORMAT',
  REGISTRATION_FAILED = 'REGISTRATION_FAILED',
  MEMORY_ERROR = 'MEMORY_ERROR'
}

interface FontError {
  type: FontErrorType
  message: string
  details: any
  timestamp: number
}
```

#### 4.2.2 错误处理策略

| 错误类型 | 重试策略 | 降级方案 | 用户提示 |
|----------|----------|----------|----------|
| 网络错误 | 重试1次，间隔1秒 | 使用内置字体 | "网络连接失败，使用备用字体" |
| 文件未找到 | 不重试 | 使用内置字体 | "字体文件缺失，使用备用字体" |
| 格式错误 | 不重试 | 使用内置字体 | "字体格式错误，使用备用字体" |
| 注册失败 | 重试1次 | 使用内置字体 | "字体注册失败，使用备用字体" |
| 内存错误 | 不重试 | 提示用户 | "内存不足，请关闭其他应用" |

### 4.3 缓存策略

#### 4.3.1 内存缓存
- **缓存位置**: 字体管理器实例
- **缓存时间**: 应用生命周期
- **缓存大小**: ~8.6MB
- **清理策略**: 应用关闭时自动清理

#### 4.3.2 持久化缓存（可选）
- **缓存位置**: localStorage (存储字体元数据)
- **缓存内容**: 字体版本、加载时间、使用统计
- **清理策略**: 字体更新时清理
